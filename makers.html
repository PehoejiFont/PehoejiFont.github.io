Font Maker’s Implementation Guide

The complete engineering recipe used for PehoejiFont’s 989 upstream forks: required glyphs, cmap coverage, anchors, copy-ready AFDKO/feaLib feature code, layout safeguards, and automated QA.

1. Glyphs and cmap

Add or verify every glyph below using AGL-compliant production names so PDF ToUnicode extraction works cleanly:

Production glyph nameCodepoint(s)How to build / notes
uni0358 (◌͘)U+0358Reuse the dot of U+0307. GDEF class 3 mark with zero advance (or a deliberate SIL-style GDEF class 1 spacing base).
uni030D (◌̍)U+030DShort vertical stroke sitting in the same vertical height band as U+0301 (acute).
uni207F (ⁿ)U+207FSuperior n (~55–65% scale, weight-compensated). Reuse n.sups if the font has sups.
uni1D3A (ᴺ)U+1D3ASuperior capital N, for all-caps nasalisation (SIᴺ).
dotlessi, uni0237U+0131, U+0237Dotless ı and dotless ȷ for the Soft_Dotted swap before above-marks (i̍).
*.case marks— (unencoded)Flattened/raised capital-form marks, triggered contextually inside ccmp (not only case).

2. Anchors (mark & mkmk)

  • top anchor on every base that can receive a tone: a e dotlessi o u m n (plus j/uni0237), all capitals, and any ccmp ligature that can still take a stacked tone (such as o_uni0358).
  • topright anchor on o O and on every precomposed toned o: ó ò ô ō ŏ and Ó Ò Ô Ō Ŏ. Because NFC sends ó + U+0358 (not o + U+0301 + U+0358), omitting even one toned base drops the dot to (0, 0).
  • Wide accents & bold weights: Inspect ō͘ ô͘ ŏ͘ in Bold/Black masters. Shift topright slightly right/down or supply narrowed accents in precomposed ligatures (similar to Vietnamese ố/ớ).
  • Base attachment, not mark-to-mark: U+0358 attaches to the base glyph via mark (topright / _topright), never stacked on top of the tone mark via mkmk.
  • Mark anchors: _top on all combining tone marks, _topright on uni0358, and top on tone marks for mkmk stacking.
  • Syllabic ng: Tone marks sit on n (n̍g, n̂g), so g needs no special anchors.
  • Variable fonts: Define matching anchors in every master and test interpolation extremes (Thin–Black, Condensed–Expanded).

3. AFDKO / feaLib feature code sketch

Anchor coordinates below are illustrative placeholders — every glyph requires its own coordinates in production sources.

poj.fea — AFDKO / feaLib OpenType feature sketch 
languagesystem DFLT dflt;
languagesystem latn dflt;
# Keep any existing languagesystem lines (latn TRK, hani, ...) and register lookups under all of them

@TopMarks = [uni0300 uni0301 uni0302 uni0303 uni0304 uni0306 uni0307 uni0308 uni030A uni030D];
@AllMarks = [@TopMarks uni0358 uni0323];

markClass [uni0300 uni0301 uni0302 uni0304 uni0306 uni030D] <anchor 0 500> @MC_top;
markClass uni0358 <anchor 0 450> @MC_topright;

table GDEF {
    GlyphClassDef
        [a e i o u m n dotlessi uni0237 oacute ograve ocircumflex omacron obreve
         o_uni0358 oacute_uni0358 o_uni030D_uni0358],   # bases (ligature outputs are BASES, not class 2)
        ,                                               # ligatures
        [@AllMarks],                                    # marks
        ;
} GDEF;

# 1. Soft-dotted i/j: drop the dot before any ccc-230 mark, skipping non-top marks in between
lookup DotlessI {
    lookupflag UseMarkFilteringSet @TopMarks;
    sub i' @TopMarks by dotlessi;
    sub j' @TopMarks by uni0237;
} DotlessI;

# 2. Precomposed POJ glyphs: longest sequences first; canonical order, NFC spelling, and reverse order
#    (DotlessI runs first, so any i-ligatures must start from dotlessi.)
lookup POJLigatures {
    sub o uni0301 uni0358 by oacute_uni0358;      # NFD, canonical
    sub o uni0358 uni0301 by oacute_uni0358;      # non-canonical (engines that do not reorder)
    sub o uni030D uni0358 by o_uni030D_uni0358;
    sub o uni0358 uni030D by o_uni030D_uni0358;
    sub oacute uni0358 by oacute_uni0358;         # NFC
    sub o uni0358 by o_uni0358;                   # 2-glyph prefix comes LAST
    # ... repeat for ò ô ō ŏ and capitals
} POJLigatures;

feature ccmp {
    lookup DotlessI;
    lookup POJLigatures;
    # Contextual capital marks, because `case` is off by default:
    # sub [A-Z ...] [@TopMarks]' by [@TopMarks.case];
} ccmp;

lookup MarkTop {
    pos base [a e dotlessi u m n uni0237 o_uni0358] <anchor 250 500> mark @MC_top;   # per-base in real fonts
    pos base o <anchor 280 500> mark @MC_top;
} MarkTop;

lookup MarkTopRight {
    pos base [o oacute ograve ocircumflex omacron obreve] <anchor 470 420> mark @MC_topright;
    # ... capitals
} MarkTopRight;

feature mark {
    lookup MarkTop;
    lookup MarkTopRight;
} mark;

feature mkmk {
    pos mark [uni0300 uni0301 uni0302 uni0304 uni0306 uni030D] <anchor 0 700> mark @MC_top;
} mkmk;

4. Eight mandatory OpenType rules

  1. Put POJ composition in ccmp, never liga or clig. Optional ligatures turn off under CSS letter-spacing and are off by default in Microsoft Word.
  2. Order ligatures longest-first and cover all three input forms (NFC ó 0358, NFD canonical o 0301 0358, and reverse o 0358 0301). While feaLib and makeotf sort ligatures longest-first within a lookup, other compilers may not.
  3. Keep anchors even when precomposed ligatures exist, so any unlisted cluster still positions cleanly.
  4. Always ship a GPOS mark feature. Never rely on HarfBuzz bounding-box fallback, which does not exist in CoreText/DirectWrite and switches off globally if any mark lookup is added later.
  5. Implement the Soft_Dotted i/j swap with UseMarkFilteringSet so intervening below-marks (such as U+0323) do not block the substitution.
  6. Assign ligature outputs GDEF class 1 (base) and include them in the font’s o/O kerning classes.
  7. Use AGL-style production glyph names (uni0358, uni030D, o_uni0358, oacute_uni0358) so PDF ToUnicode reconstruction works. Custom names like oopoj_acutecomb copy out of PDFs as garbage. (Note: dotlessi + uni030D may still copy out as ı̍ unless the PDF emitter writes /ActualText.)
  8. Do not place POJ rules inside locl, and verify new ccmp lookups do not break existing locl Turkish/Azerbaijani/Lithuanian (TRK/AZE/LTH) dotted-i rules.

5. Additional engineering checks

  • Vertical metrics: O̍͘, M̍, and Ó͘ reach higher than standard Western European diacritics. Raise OS/2.usWinAscent and hhea.ascender enough to prevent clipping on Windows and inside tight CSS line boxes.
  • Collision after o͘: A zero-width dot can clash with tall following glyphs in o͘h, o͘k, o͘l, o͘t, o͘ⁿ, o͘", and o͘’. Add modest right sidebearing to precomposed o͘ ligatures, or add contextual kerning after uni0358.
  • Small caps (smcp / c2sc): Provide .sc versions of precomposed POJ ligatures, or carefully order ccmp vs smcp lookups so small caps retain proper anchors and dots.
  • CFF / CFF2 vs TrueType (glyf): TrueType composites make Technique B very cheap in file size. CFF/CFF2 has no glyph components, so every precomposed ligature duplicates outline data across every master. Carefully hint the thin vertical stroke of U+030D so it does not drop out at small screen sizes.
  • Variable fonts: Precomposed ligatures multiply outline drawing across masters, favouring Technique A (anchors) combined with TrueType composites where possible.
  • Double hyphen (--): Ensure no liga or calt rule converts -- into an en-dash, and keep sidebearings open so the two hyphens do not touch.

6. Visual QA checklist

Verify every built font by eye across real platforms:

  1. Paste the full POJ test line (NFC, NFD, and reverse order) in Chrome / Firefox (HarfBuzz), Safari / Pages (CoreText), and Microsoft Word (DirectWrite).
  2. Test in a browser with letter-spacing: 0.1em to verify zero dependence on optional liga.
  3. Check all weights and masters — especially wide accents (ō͘ ô͘ ŏ͘) and capitals (O͘ Ó͘ Ō͘ O̍͘) in Bold.
  4. If publishing to Google Fonts, verify the live CSS unicode-range slices actually deliver U+0358, U+030D, and U+207F.
