Google Fonts Survey & 989 Upstream Forks

PehoejiFont’s mission is adding Pe̍h-ōe-jī (POJ) support to open-source fonts from the Google Fonts catalog and contributing those changes back upstream.

License survey (2,067 families)

Source: google/fonts at commit cc5661d (2026-11-19). Every family’s license permits modifying the font and releasing the derivative publicly; the critical distinction is whether a released fork may keep the original font name.

LicenseFamiliesReleased fork can keep name?
SIL OFL 1.1, no Reserved Font Name (RFN)1,460Yes
SIL OFL 1.1, with Reserved Font Name558No — must be renamed
Apache 2.044Yes (keep license & notices, state changes)
Ubuntu Font Licence 1.05No — must be renamed

OFL derivatives must remain under the OFL and cannot be sold by themselves. When changes are merged by the font’s own upstream maintainers, the official release keeps its original name in every case. Per-family raw metadata is stored in data/google-fonts.json.

Shortlist & coverage breakdown (1,471 families)

PehoejiFont focuses on Google Fonts families satisfying three conditions:

  1. Open license (SIL OFL 1.1 or Apache 2.0).
  2. No Reserved Font Name, so modified builds can be released under the same name.
  3. Source repository hosted on GitHub, so changes can be contributed upstream as pull requests.

We downloaded and checked the main font file of each of the 1,471 shortlisted families for the three core POJ characters (U+0358, U+030D, U+207F), the five combining tone marks, and the GPOS mark feature:

Breakdown of the 1,393 families that need work:

  • 1,242 are missing all three POJ characters (U+0358, U+030D, U+207F).
  • 371 are also missing one or more standard combining tone marks.
  • 365 have no GPOS mark positioning feature at all, so anchors must be built from scratch.

Upstream fork directory (989 repositories)

The 1,393 families needing work map to 989 unique GitHub repositories (excluding googlefonts/googlefontdirectory-hg, an archive of the legacy Mercurial directory rather than an active upstream source). Each repository is forked into the PehoejiFont GitHub organization on its default branch.

Contribution workflow for each font

  1. Add or reuse glyphs in the fork’s sources:
    • U+030D: reuse a vertical stroke or adapt the acute accent stroke weight;
    • U+0358: reuse the dot from U+0307;
    • U+207F (and U+1D3A): superior n / N.
  2. Add mark and mkmk anchors (plus ccmp dotless-i and optional precomposed glyphs) so marks attach cleanly on a e i o u m n (upper and lower case) and every toned o. See the Font Maker’s Guide.
  3. Build with the project’s native build pipeline and validate the rendered POJ syllables across browsers and platforms.
  4. Open an upstream pull request. Once the upstream project cuts a release, Google Fonts picks up the new version and the family keeps its original name.

Upstream ecosystem efforts

  • googlefonts/glyphsets#5 (open since 2020): proposes adding U+030D, U+0358, and U+207F to the GF Latin Plus glyph set. Adoption would make POJ coverage part of Google Fonts’ standard requirements.
  • googlefonts/lang: currently has no language definition for Taigi in Latin script (nan_Latn). Adding nan_Latn would enable Google Fonts’ tooling and web catalog to automatically detect and report POJ support.
