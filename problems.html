Fix common problems

What you see, why it happens, and what to do.

I see empty boxes (□) instead of letters

Why: the font doesn't have that character at all. EB Garamond, for example, has no o͘ dot.

Fix: switch to a font from the list.

The dot of o͘ is far to the right, or floating high

Why: the font has the dot but doesn't know where to put it (see way D). It is usually worst on capitals such as Ó͘.

Fix: switch fonts. Adding extra spaces or moving the dot by hand will break on someone else's screen.

One letter looks different from the rest of the word

Why: the font lacks that letter, so the app quietly borrows it from another font. Letters often borrowed: ḿ ǹ, the o͘ dot, the 8th-tone line. On a Mac, for example, EB Garamond borrows the o͘ dot from Helvetica.

Fix: use a font that has every POJ letter (test it).

There is a dot under the tone line on i̍

Why: the font doesn't remove the i's own dot when a tone is added (explained here).

Fix: switch fonts. Don't type a dotless ı by hand: the word will no longer match searches.

The text looked fine until I added letter-spacing (or opened it in Word)

Why: the font builds POJ letters with an optional feature (“ligatures”) that browsers switch off under letter-spacing and that Word leaves off by default.

Fix: use a font that builds POJ letters with the always-on feature. All fonts in our list do. In Word you can also turn ligatures on under Font → Advanced.

thiⁿ turned into thin

Why: a program “normalised” the text with NFKC, which turns ⁿ into a plain n (explained here).

Fix: if you run the system, set it to NFC, not NFKC. Otherwise report it to whoever runs it.

Search can't find a word I can see on screen

Why: the word is stored in a different form from what you typed (same letter, different codes), or it uses a look-alike such as o· or ơ.

Fix: convert the text to NFC once, and replace look-alikes with the real o͘.

tńg--khì became tńg–khì

Why: the word processor auto-corrected two hyphens into a dash.

Fix: turn off “replace hyphens with dash” in the auto-correct settings.

My website shows the dots wrong but my computer doesn't

Why: the website probably loads the font from Google Fonts, which leaves out the POJ pieces for some fonts (the Google Fonts trap).

Fix: host the full font file on your own site.

Old documents show strange symbols after I changed the font

Why: the document was typed with an old POJ font that used private codes. Those codes mean nothing in any other font.

Fix: convert the document to real Unicode POJ once. After that it works in every font.

Mac and Windows

Phones, Chrome and Firefox all use the same text engine (HarfBuzz), which we tested in detail. Macs and Windows also have their own engines, which are used by Safari, Pages, Word and other built-in apps.

  • Mac (first results): we ran the same tests through the Mac's own engine. Lesson One, jf open 粉圓, 芫荽 Iansui, I.Ming, GenYo Min and WD-XL Lubrifont gave exactly the same result as Chrome for every test letter. Fonts that depend on the browser's guess (Helvetica, Menlo, the 字咍 Taigi fonts) look different on a Mac. More results are coming.
  • Windows: not tested yet.

Fonts with ready-drawn letters and snap points (ways A + B) depend least on the engine, which is one more reason to choose them.
