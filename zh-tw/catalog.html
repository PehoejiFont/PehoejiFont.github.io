Google Fonts 普查與 989 個上游 Fork

PehoejiFont 計畫的核心目標，是為 Google Fonts 目錄中的開源字型補上白話字（Pe̍h-ōe-jī，POJ）支援，並將修改以 Pull Request 貢獻回各字型的上游專案。

授權與保留名稱普查（2,067 款家族）

資料來源：google/fonts（commit cc5661d，2026-11-19）。每一款字型的授權皆允許修改並公開釋出衍生版本；差別在於「公開釋出的修改版分支能否保留原本的字型名稱」。

授權條款家族數釋出修改版能否保留原字型名稱？
SIL OFL 1.1，無保留字型名稱（RFN）1,460可以
SIL OFL 1.1，設有保留字型名稱（RFN）558不行 — 必須改名
Apache 2.044可以（保留授權與聲明、標註變更）
Ubuntu Font Licence 1.05不行 — 必須改名

OFL 衍生字型必須持續採用 OFL 且不可單獨販售。若修改被原本的上游專案合併釋出，無論原授權是否含 RFN，官方新版都能保留原名。逐家族原始資料見 data/google-fonts.json。

候選清單與字元覆蓋分析（1,471 款家族）

本計畫優先投入同時符合以下三個條件的字型家族：

  1. 採用開源授權（SIL OFL 1.1 或 Apache 2.0）。
  2. 無保留字型名稱（RFN），確保衍生版本可直接沿用原名釋出。
  3. 原始碼儲存庫位於 GitHub，方便以 Pull Request 回饋上游。

989 個上游 Fork 儲存庫目錄

上述 1,393 款待補字家族對應至 989 個獨立 GitHub 儲存庫（已排除舊 Mercurial 歷史封存庫 googlefonts/googlefontdirectory-hg）。這 989 個專案均已僅擷取預設分支 Fork 至 PehoejiFont GitHub 組織。

單一字型專案的貢獻流程

  1. 在 Fork 原始檔中新增或重用字形：
    • U+030D：重用垂直筆畫，或參考銳音符筆粗調整；
    • U+0358：重用 U+0307 的圓點；
    • U+207F（與 U+1D3A）：上標 n／N。
  2. 補齊 mark 與 mkmk 錨點（以及 ccmp 無點 i 與選用預繪字形），使調號能準確附著於 a e i o u m n 大小寫與全部帶調 o。詳見字型開發者實作指南。
  3. 以該專案原有建置流程編譯字型，並使用 fontbakery 與本站的POJ 檢測與樣張腳本驗證。
  4. 向上游開立 Pull Request。待上游專案發布新版後，Google Fonts 即會自動收錄更新，並保有原本的字型名稱。

上游生態系標準推動

  • googlefonts/glyphsets#5（自 2020 年開啟）：提案將 U+030D、U+0358 與 U+207F 納入 GF Latin Plus 字集；一旦通過，POJ 支援將成為 Google Fonts 官方標準要求之一。
  • googlefonts/lang：目前尚無拉丁文台語（nan_Latn）的語言定義。新增 nan_Latn 後，Google Fonts 檢測工具與官網篩選即可自動辨識並標示支援 POJ 的字型。
