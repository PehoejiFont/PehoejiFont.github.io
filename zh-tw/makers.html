字型開發者實作指南（OpenType 配方）

本頁整理 PehoejiFont 為 989 個上游 Fork 設計的完整工程配方：必備字形與 cmap、錨點配置、可直接複製的 AFDKO／feaLib 功能碼、八項強制規範與自動化檢驗指令。

1. 必備字形與 cmap

請使用符合 AGL 規範的正式字形名稱（production glyph names），確保 PDF ToUnicode 擷取文字不會亂碼：

正式字形名稱Unicode 字碼製作方式與說明
uni0358（◌͘）U+0358沿用 U+0307 的圓點。設為 GDEF 類別 3 零寬附加符號（或明確採用 SIL 風格的 GDEF 類別 1 佔位基礎字形）。
uni030D（◌̍）U+030D短豎線，垂直高度帶應與 U+0301（銳音符）一致。
uni207F（ⁿ）U+207F上標 n（約縮放 55–65% 並補償筆粗）；若字型已有 sups 可直接重用 n.sups。
uni1D3A（ᴺ）U+1D3A上標大寫 N，供全大寫鼻化標題（SIᴺ）使用。
dotlessi、uni0237U+0131、U+0237無點 ı 與無點 ȷ，供上方附加符號前執行 Soft_Dotted 替換（i̍）。
*.case 調號—（不編碼）大寫專用的壓扁／抬高調號，請在 ccmp 以上下文觸發（切勿只寫在 case）。
預組複合字元ḿ Ḿ ǹ Ǹ ń Ń ŏ Ŏ ĭ Ĭ ă Ă ĕ Ĕ ŭ Ŭ ā ē ī ō ū Ā Ē Ī Ō Ū完整收錄 Unicode 17.0 所有 POJ 預組字母，避免不會自動分解的引擎（CoreText／DirectWrite）觸發系統補字。

2. 錨點配置（mark 與 mkmk）

  • top 錨點：設於所有可標聲調的基礎字母：a e dotlessi o u m n（以及 j／uni0237）、全部大寫字母，以及仍可能加標聲調的 ccmp 連字（如 o_uni0358）。
  • topright 錨點：設於 o O 以及每一個預組帶調 o：ó ò ô ō ŏ 與 Ó Ò Ô Ō Ŏ。因 NFC 送入的是 ó + U+0358，只要漏掉任一個帶調基礎字，圓點就會掉到 (0, 0)。
  • 寬調號與粗體字重：務必檢查 Bold／Black 字重下的 ō͘ ô͘ ŏ͘；必要時微調 topright 往右下偏移，或在預繪連字中略微收窄調號（仿越南文 ố／ớ）。
  • 直接掛在基礎字上，非 mkmk：U+0358 必須透過 mark（topright／_topright）掛在基礎字母上，切勿用 mkmk 疊在聲調符號上方。
  • 附加符號端錨點：各組合聲調設 _top、uni0358 設 _topright，並在聲調上加設 top 供 mkmk 堆疊。
  • 韻化 ng：聲調落在 n 上（n̍g、n̂g），g 不需額外錨點。
  • 可變字型（Variable Fonts）：每個 Master 都必須設定一致的錨點，並在極端軸值（Thin–Black、Condensed–Expanded）檢查內插位置。

3. AFDKO / feaLib 功能程式碼範本

下列錨點座標僅為示意佔位值，實際製作時請依各字形輪廓填入正確座標。

poj.fea — AFDKO / feaLib OpenType 功能範本 
languagesystem DFLT dflt;
languagesystem latn dflt;
# 請保留原字型既有的 languagesystem（如 latn TRK、hani 等）並於其下註冊 lookups

@TopMarks = [uni0300 uni0301 uni0302 uni0303 uni0304 uni0306 uni0307 uni0308 uni030A uni030D];
@AllMarks = [@TopMarks uni0358 uni0323];

markClass [uni0300 uni0301 uni0302 uni0304 uni0306 uni030D] <anchor 0 500> @MC_top;
markClass uni0358 <anchor 0 450> @MC_topright;

table GDEF {
    GlyphClassDef
        [a e i o u m n dotlessi uni0237 oacute ograve ocircumflex omacron obreve
         o_uni0358 oacute_uni0358 o_uni030D_uni0358],   # 基礎字形（預繪連字成品須為類別 1 base，非類別 2）
        ,                                               # ligatures
        [@AllMarks],                                    # marks
        ;
} GDEF;

# 1. Soft_Dotted i/j：遇到任何 ccc-230 上方附加符號即去點，並忽略中間的其他附加符號
lookup DotlessI {
    lookupflag UseMarkFilteringSet @TopMarks;
    sub i' @TopMarks by dotlessi;
    sub j' @TopMarks by uni0237;
} DotlessI;

# 2. 預繪 POJ 連字：最長序列優先；同時涵蓋標準順序、NFC 與非正規反向順序
#    （DotlessI 先執行，因此任何 i 連字皆須從 dotlessi 出發）
lookup POJLigatures {
    sub o uni0301 uni0358 by oacute_uni0358;      # NFD 標準順序
    sub o uni0358 uni0301 by oacute_uni0358;      # 非正規順序（相容不重排的引擎）
    sub o uni030D uni0358 by o_uni030D_uni0358;
    sub o uni0358 uni030D by o_uni030D_uni0358;
    sub oacute uni0358 by oacute_uni0358;         # NFC
    sub o uni0358 by o_uni0358;                   # 2 字形規則排在最後
    # ... 依序補齊 ò ô ō ŏ 與所有大寫
} POJLigatures;

feature ccmp {
    lookup DotlessI;
    lookup POJLigatures;
    # 大寫調號請以 ccmp 上下文替換，因為 `case` 預設關閉：
    # sub [A-Z ...] [@TopMarks]' by [@TopMarks.case];
} ccmp;

lookup MarkTop {
    pos base [a e dotlessi u m n uni0237 o_uni0358] <anchor 250 500> mark @MC_top;   # 實際字型應逐字定座標
    pos base o <anchor 280 500> mark @MC_top;
} MarkTop;

lookup MarkTopRight {
    pos base [o oacute ograve ocircumflex omacron obreve] <anchor 470 420> mark @MC_topright;
    # ... 大寫字母
} MarkTopRight;

feature mark {
    lookup MarkTop;
    lookup MarkTopRight;
} mark;

feature mkmk {
    pos mark [uni0300 uni0301 uni0302 uni0304 uni0306 uni030D] <anchor 0 700> mark @MC_top;
} mkmk;

4. 八項必守 OpenType 工程規則

  1. POJ 組字一律寫在 ccmp，絕不可放進 liga 或 clig。選用連字會在 CSS letter-spacing 下關閉，且 Word 預設關閉。
  2. 連字規則最長優先，並同時覆蓋三種輸入形式（NFC ó 0358、NFD 標準 o 0301 0358、反向 o 0358 0301）。雖然 feaLib／makeotf 會自動排序，其他編譯器未必如此。
  3. 即便做了預繪連字，仍須保留完整錨點，作為未列出組合的安全網。
  4. 務必附上 GPOS mark 功能。絕不可仰賴 HarfBuzz 外框盒備援，因 CoreText／DirectWrite 不具此備援，且日後一旦加入任何 mark 查表便會全面失效。
  5. 以 UseMarkFilteringSet 實作 Soft_Dotted i/j 替換，避免中間夾雜下方附加符號（如 U+0323）時阻斷替換。
  6. 將預繪連字成品標為 GDEF 類別 1（base），並加入 o／O 的字偶距（kerning）群組。
  7. 使用 AGL 規範的正式字形名稱（uni0358、uni030D、o_uni0358、oacute_uni0358），讓 PDF ToUnicode 正確還原文字；自訂名稱如 oopoj_acutecomb 會導致 PDF 複製亂碼。（註：dotlessi + uni030D 在 PDF 中仍可能複製成 ı̍，PDF 產出工具宜寫入 /ActualText。）
  8. 切勿把 POJ 規則寫進 locl，並確認新增的 ccmp 不會破壞既有土耳其語／亞塞拜然語／立陶宛語（TRK／AZE／LTH）的 locl 帶點 i 規則。

5. 其他進階工程檢查

  • 垂直度量（Vertical Metrics）：O̍͘、M̍、Ó͘ 比一般西歐重音更高；請適度拉高 OS/2.usWinAscent 與 hhea.ascender，避免在 Windows 或較緊的 CSS 行高被截切。
  • o͘ 後方的碰撞避讓：零寬圓點容易撞到 o͘h、o͘k、o͘l、o͘t、o͘ⁿ、o͘"、o͘’ 等高筆畫字元；請為預繪 o͘ 字形增加些許右側留白，或在 uni0358 後加入上下文微調字距。
  • 小型大寫（smcp / c2sc）：請提供 .sc 版預繪連字，或妥善安排 ccmp 與 smcp 順序。
  • CFF / CFF2 與 TrueType（glyf）：TrueType 複合組件（composites）讓方式 B 幾乎不增加檔體大小；CFF／CFF2 沒有組件機制，每個預繪連字在每個 Master 都會複製一份輪廓。此外請細心微調細長 U+030D 的 hinting，避免小字號消失。
  • 可變字型：預繪連字會讓多 Master 繪製成本倍增，因此較傾向以方式 A（錨點）搭配 TrueType 複合字形為主。
  • 雙連字號（--）：確認無任何 liga／calt 將 -- 轉為破折號，且兩條連字號間保留明確間距。

6. 目視 QA 驗收清單

請於實際跨平台環境目視驗收每款編譯完成的字型：

  1. 將完整 POJ 測試字串（NFC、NFD 與反向順序）貼入 Chrome／Firefox（HarfBuzz）、Safari／Pages（CoreText）與 Microsoft Word（DirectWrite）逐一檢查。
  2. 在瀏覽器中加上 letter-spacing: 0.1em，確認完全不依賴選用 liga。
  3. 檢查所有字重與可變軸極端值——特別是粗體下的寬調號（ō͘ ô͘ ŏ͘）與大寫（O͘ Ó͘ Ō͘ O̍͘）。
  4. 若預計上架 Google Fonts，務必確認實際送出的 CSS unicode-range 切塊確實包含 U+0358、U+030D 與 U+207F。
